●myWall User Manual

UI v4.1 · i18n branch

A practical guide to the personal DVD/Blu-ray wall: upload close-up photos, identify and catalog spines, browse metadata, and locate a physical disc with the wall AR overlay.

This manual describes the experimental i18n branch, whose default interface and content locale are English. The stable main branch remains a separate Chinese-only release.

1. Interface overview

  • Panoramic wall: the central background. Disc markers, location rings, and translucent close-up overlays are drawn over it. The brightness control above the bottom Tools tray changes only the wall photo (about 30%–100%, default 50%), not markers; the browser remembers the value.
  • Left sidebar: title and version, edit lock, list/folder switch, search, filters, disc cards, manual button, and compact language chips. The bottom Tools bar slides up to show Upload & Scan, Add Disc, Image Management, and Complete Posters.
  • Right detail panel: appears after selecting a disc and shows its poster, metadata, synopsis, source-photo location, AR location controls, and edit action.

Open this manual with the book icon. /static/docs/manual.en.html is the canonical English source. The compatibility entry at /static/docs/manual.html forwards to the same English manual, so every UI locale currently receives complete English documentation.

Read-only and editable modes

The outline lock beside v4.1 controls all write operations:

  • Locked (default): browse, search, filter, inspect details, use AR location, adjust wall brightness, zoom, and move panels. Write controls report read-only mode.
  • Unlocked (green): edit or delete discs, add cards, upload and recognize, run Stage2, complete posters, change preference or recognition flags, edit boxes, and place close-ups.

The desktop state is stored as mywall-edit-unlocked in localStorage and applies immediately. Mobile layouts are always read-only, ignore a desktop unlock state, and hide the lock.

Phone layout

The wall is pinned above the scrolling catalog. Hold the short handle at the top of the sidebar sheet and swipe up to hide the wall for card browsing; swipe down to reveal it for AR. Normal vertical scrolling in the list remains available.

Complete manual-first workflow (no vision model required)

Automatic analysis and Stage2 require a reachable local vision model. They are optional: the following workflow can build a complete wall using manual cards plus TMDb, OMDb, or TVDB metadata.

  1. Unlock editing on a desktop browser.
  2. Open Tools → Upload & Scan and upload a spine close-up or panorama. Analysis may be skipped.
  3. Open the spine-box editor and draw, resize, add, or remove boxes to match the physical spines.
  4. Run Stage2 only if LM Studio is available; otherwise continue manually.
  5. Choose Tools → Add Disc. Enter at least an English or Chinese title and optionally associate the uploaded image.
  6. Choose media type and source, search TMDb / IMDb (through OMDb) / TVDB, then select a candidate. Never invent a tmdb_id.
  7. With a valid TMDb ID, use Refresh from TMDb or Complete Posters to fill missing artwork.
  8. Place the close-up on the panoramic wall. A positioned disc can then be found with the AR overlay.
  9. Use the same Flask address on a phone for read-only wall, list, details, and location viewing.

API keys are maintained in the collapsed API Key section of the Edit Disc / Add Disc dialog. They are masked in the UI and saved only to local data/api_keys.json.

Build or deploy the optional Stage2 vision service

Recognition uses a local or LAN LM Studio OpenAI-compatible endpoint at /v1/chat/completions, not a hosted vision API.

  1. Install LM Studio.
  2. Download and load a vision model. The configured default is zai-org/glm-4.6v-flash; use VISION_MODEL to select another loaded model or VISION_MODEL_AUTO=1 to use the preference list.
  3. Start LM Studio Local Server, commonly on port 1234.
  4. Set LMSTUDIO_BASE in the environment or config.py (default http://127.0.0.1:1234). Use the server computer’s LAN address when Flask runs elsewhere.
  5. Confirm the Flask host can reach that endpoint through routing and firewall rules.
  6. Outbound metadata APIs may use HTTP_PROXY/HTTPS_PROXY. If a system tunnel intercepts LAN traffic, bypass the local subnet so LM Studio stays reachable.

If no model is available, Analyze and Stage2 will fail. Use the manual-first workflow; recognition is not required to catalog a collection.

Screenshot policy

Legacy screenshots were removed because they showed the Chinese stable UI and included a private collection wall. Add only English-UI screenshots that contain no private photos, credentials, or personal library data.

2. Dragging the sidebar and detail panel

The gray handle at the top of each desktop panel lets you uncover the wall:

  • Drag sidebar: move the left panel horizontally.
  • Drag panel: move the open right detail panel horizontally.
  • Double-click: reset that panel’s offset to zero.
  • Keyboard: focus a handle and press ←/→; hold Shift for larger steps.

Offsets are stored in the browser and restored on the next visit.

3. List and folder views

List view

Shows every disc as a flat card. The primary line follows the selected content locale and falls back to available title fields; the secondary line avoids repeating the same title. Select a card to open details. The preference heart sits under the year, and the compact right column contains Locate, Edit, recognition flag, and Delete. In read-only mode only Locate remains active.

Folder view

Groups cards by source close-up (source_image). Select a group header to expand or collapse it. When editing is unlocked, select the group thumbnail to adjust that close-up’s placement on the wall. Cards inside a group behave exactly like list cards.

4. Search, filters, and Hot Words

  1. Enter a title, synopsis, director, or cast term. Search is debounced; Enter or the search button also submits. Person-name matching normalizes spaces, common hyphens, and CJK middle-dot variants.
  2. Combine the text query with Genre, Year, and Preference. Genre matching understands normalized English/Chinese aliases without rewriting stored source labels.
  3. Preference options are All, green, blue, orange, and unmarked, corresponding to stored values all / 1 / 2 / 3 / 0.
  4. The result counter reports the current number of matching discs.

Hot Words genre cloud

On desktop, select the cloud icon at the end of the filter row. Word size is based on the full-library genre count, not the current filtered list. Select a word to filter; drag beyond the movement threshold to reposition it. Nearby words react without overlap, and the cluster settles back toward a heat-weighted center. The stable layout does not repack when a disc is selected or a filter highlight changes.

The panel can be resized from its edges and corners; size is remembered locally. It repacks after first open, a completed resize, or a meaningful width change. Close it with its close control, Esc, or a click outside. The entry is hidden on narrow/mobile layouts.

5. Disc details, source position, and wall AR

Open details

Select a card in either view. The right panel shows poster, year, rating, genres, synopsis, directors, and cast when those fields exist.

Position in the source photo

  • A disc with a source image shows its original thumbnail and highlighted spine box.
  • Select the source image for a full-screen translucent AR Zoom view.
  • Reselect box lets an unlocked desktop user draw the region again and update or re-recognize it.

Locate on the physical wall

  1. Select Locate in details or use the locate icon on a card.
  2. The panorama shows a spreading ring and title bubble. If its source close-up has placement data, that region also appears as a translucent aligned overlay.
  3. If wall coordinates are absent, myWall reports that the position has not been marked.

The locate icon distinguishes a disc with a calibrated source-photo box from one whose original-photo position is unknown.

6. Edit discs, add cards, metadata search, and API keys

A. Edit an existing disc

  1. Unlock editing, then select the pencil icon or Edit in details.
  2. The source comparison area shows the close-up and current spine box. Zoom with the wheel or ± controls, pan by dragging, and use Locate spine to zoom to the text. If no box exists, the full image remains visible and the dialog directs you to Reselect box.
  3. Edit English/Chinese titles, release year, optional TMDb / IMDb / TVDB IDs, and the associated source image.
  4. Choose media type (All / Movie / Series) and source (All / TMDb / IMDb / TVDB), then run one title search. Enabled and configured sources are queried in parallel; same-title, same-year candidates from different services remain separate.
  5. Select a candidate to fill the best available title, year, poster, and source ID. TMDb results set tmdb_id and media type; OMDb/TVDB results set imdb_id/tvdb_id without fabricating a TMDb ID.
  6. Refresh from TMDb uses an existing TMDb ID to fill artwork and metadata while preserving dialog title/year and all box coordinates. Without an ID, it starts with search.
  7. Save updates the record through PUT /api/discs/:id.

B. API keys (desktop only)

  • Expand API Key in Edit Disc or Add Disc. TMDb, IMDb (OMDb), and TVDB each have a masked value and an enabled switch.
  • A stored key appears like ••••abcd; the full value is never returned to the browser. Paste a replacement, save it, or explicitly clear it.
  • Disabled sources send no requests. An enabled source without a key stays visibly unavailable and does not fake search results.
  • Keys are saved to local data/api_keys.json, not the SQLite library and not Git. The UI refreshes source availability immediately.

C. Add Disc (manual card, no Stage2)

  1. Open Tools → Add Disc; it uses the same dialog as editing.
  2. Enter at least one English or Chinese title. Year and external IDs are optional.
  3. Optionally associate an existing close-up or panorama. A card can be created with no source_image and boxed later.
  4. Use the same type/source search and candidate selection flow, or enter trusted IDs directly.
  5. Save creates the record through POST /api/discs, refreshes the list, and opens its details.

D. Complete Posters

Tools → Complete Posters fills missing posters in bulk from existing tmdb_id and tmdb_media_type values. It does not change titles, source boxes, or wall coordinates. A reachable TMDb service and configured key are required.

7. Place close-up photos on the wall

  1. Switch to Folder view and unlock editing.
  2. Select the thumbnail at the left of a source-image group.
  3. The tray lists all close-ups. Select or drag one onto the wall to start editing it.
  4. Drag inside the frame to move it and use corner handles to resize it. Switch among tray images to calibrate several close-ups in one session.
  5. Keep “recalculate discs from photo_offset after saving” enabled when all disc markers under that image should follow the new transform.
  6. Select Save position, or cancel/close the overlay without saving.

Upload step 4 also supports batch placement with drag, lower-right resize, and wheel controls. Stage2 may import discs before width_ratio/height_ratio is calibrated; their wall coordinates can be recalculated later.

8. Upload and recognition workflow

Unlock editing and choose Tools → Upload & Scan. The uploaded-photo list supports both the classic batch path and the higher-accuracy manual-box → Stage2 path.

A. Classic four-step batch analysis

  1. Upload: drag or choose one or more JPG, PNG, or WebP close-ups. Existing photos can be selected for deletion or re-analysis.
  2. Analyze: the backend runs OCR/vision in batches and reports progress.
  3. Match: review metadata candidates, change a match, search manually, calibrate the spine, or visually verify it. Finish with Confirm all matches and save.
  4. Placement: place this batch of photo frames over the panoramic wall, then save or skip.

B. Manual spine boxes → Stage2 (recommended for accuracy)

  1. In Uploaded Photos, select one image or use the outline crop icon on its thumbnail.
  2. Choose Edit spine boxes (exactly one image must be selected) to open the embedded editor.
  3. Start from an empty canvas by dragging a box or choosing Add box, or refine existing boxes. Save to the server with the button or S; the thumbnail badge reports the saved box count.
  4. Select one or more photos that already have boxes, then choose Stage2 Recognition.
  5. The background job reads each cropped title, matches metadata, and writes discs. By default it replaces older discs associated with that same image. Progress appears in the analysis area.

Stage2 requires reachable LM Studio and TMDb services. It cannot start for an image with no saved boxes.

Closing the upload dialog may discard visible progress tracking; confirm the warning before leaving a running job.

9. Image management

  1. Unlock, then open Tools → Image Management. The grid labels uploaded items as close-up or panorama.
  2. For one image, re-run recognition or delete it.
  3. Select multiple images for batch re-recognition or deletion; Select all is available.

Spine boxes are stored under data/spine_boxes/ by wall_image.id; Stage2 output is under data/spine_results/. Deleting an uploaded image primarily removes the database/uploaded asset, so an orphaned box JSON may require manual cleanup.

10. Spine-box tools

In the main application

  • Upload list: Edit spine boxes or the thumbnail crop icon opens the embedded editor and saves boxes to the server.
  • Upload matching: Calibrate spine draws a single-disc box over the source image; use the wheel to zoom and right/middle drag to pan.
  • Details: Reselect box uses the online editor to correct source position and optionally re-recognize that region.

Standalone offline editor

Open /static/spine_boxes_editor.html to correct stage1 spine_boxes_*.json:

  1. Load the original image and stage1 JSON.
  2. Move/resize boxes, drag on empty space or use Add box for missed spines, and copy/delete as needed.
  3. Export spine_boxes_*_edited.json for offline Stage2/import.

The embedded and offline modes share editing behavior; embedded mode adds direct server save and does not require local file selection.

Offline script relationship

  • Web Stage2 roughly combines scripts/recognize_spines_with_tmdb.py and scripts/import_spines_to_db.py.
  • scripts/generate_spine_boxes.py remains the offline stage1 detector. The web flow may instead start with manually drawn empty boxes.
  • scripts/_batch_stage2.py provides a command-line batch example.

11. Card actions, preference, and keyboard behavior

  • Preference heart: outline means unmarked; solid green, blue, or orange are three preference levels. Hover to slide out the color strip, select a color, select the active color again, or choose the outline to clear it. Leaving without selecting makes no change.
  • Action column: Locate, Edit, recognition flag, and Delete are compact outline icons. Color indicates state (for example positioned green, flagged orange, Delete hover red).
  • Recognition flag: marks or clears a suspected recognition error; the wall marker also receives a warning style.
  • Delete: removes the disc after a double confirmation.
  • While unlocked, hold Shift and drag a disc marker on the wall to update its coordinates.
  • Select blank wall space to close the detail panel.
  • Esc closes the topmost AR zoom, box editor, manual, placement dialog, detail, or management overlay.

Preference, flags, deletion, editing, and marker dragging are disabled in read-only mode.

12. Services, API configuration, and local data

Flask service

  • Start from the project root with python app.py or an equivalent Flask launcher.
  • The default listener is 0.0.0.0:5000; browse locally at http://127.0.0.1:5000.
  • Routes include /static/…, /uploads/…, /photos/…, and /docs/screenshots/….

API-key precedence and safety

  • The preferred desktop UI stores TMDb, OMDb, and TVDB settings in ignored data/api_keys.json. Flask reads updates without restart.
  • GET /api/settings/keys returns only masks and enabled state; PUT updates one source.
  • Resolution order is an explicit JSON api_key (including empty for cleared), then environment variables, then config.py.
  • Never put a real key in this manual or commit one to the repository.

Metadata providers

  • TMDb: title search, details, genres, credits, and posters. Configure TMDB_API_KEY/TMDB_ACCESS_TOKEN or the UI. Apply at themoviedb.org/settings/api.
  • OMDb: legitimate IMDb-linked search and posters; writes optional imdb_id. Configure OMDB_API_KEY. Apply at omdbapi.com/apikey.aspx.
  • TheTVDB v4: series/movie search, optional tvdb_id, and posters when available. Configure TVDB_API_KEY or THETVDB_API_KEY. See thetvdb.com/api-information.

Proxy and local vision

  • Metadata clients read HTTP_PROXY/HTTPS_PROXY (including lowercase forms) and can fall back to config.TMDB_HTTP_PROXY.
  • LM Studio defaults to http://127.0.0.1:1234. Analyze, Stage2, and region recognition depend on its OpenAI-compatible endpoint.
  • A proxy should carry outbound metadata traffic without intercepting the local/LAN LM Studio endpoint.

Local files

  • Library: data/mywall.db.
  • Local API settings: data/api_keys.json (ignored by Git).
  • Uploaded assets: uploads/; wall/source photos: photos/.
  • Boxes: data/spine_boxes/{wall_image_id}.json; Stage2 results: data/spine_results/{id}.json.
  • Application log: app.log.

13. Language switching and content locale

  • The i18n branch defaults both UI locale and content locale to English.
  • Use the compact language chips at the top right of the sidebar to select English, Simplified Chinese, Japanese, or Korean.
  • The selected chip changes the UI locale for buttons, labels, dialogs, and messages, and stores it as mywall.uiLocale. All locales currently open the same complete English manual.
  • Content locale controls preferred titles, synopses, people, and genre labels and is stored separately as mywall.contentLocale. Switching the flag does not overwrite it.
  • Supported locale codes are en | zh | ja | ko. Missing UI keys fall back to English, then the key name. Missing content falls back to English, then original/legacy fields.

English and Simplified Chinese UI dictionaries are implemented. Japanese and Korean locales can be selected and remembered, but incomplete entries display the English fallback. Do not interpret a selectable chip as proof of complete Japanese/Korean UI or four-language content coverage.

14. Known conventions and operational notes

  • main and i18n are intentionally independent. Starting or testing one branch does not update the other.
  • The i18n default is English. Legacy English/Chinese database fields remain readable while localized JSON fields are introduced; missing translations are expected to fall back.
  • A metadata result from IMDb/OMDb or TVDB must not be stored as a fabricated TMDb ID.
  • Image placement and a disc’s spine box are separate calibrations: the box locates the disc inside a close-up; placement maps that close-up onto the panorama.
  • Mobile is a deliberate read-only viewer. Perform library maintenance on desktop.
  • When Flask runs with DEBUG=False, restart it after changing Python routes or backend code. Static manual changes may still require a reload because of browser caching.
  • Keep databases, uploaded photos, recognition output, and credentials local and out of commits.
