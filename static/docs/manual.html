1. 界面概览

  • 全景墙：中央背景；碟片标记、定位环、特写半透明覆盖都叠在墙上。侧栏底栏「功能」上方可调墙图明暗（约 30%–100%，默认 75%），只暗照片、不暗标记；浏览器会记住。
  • 左面板：标题（含版本号）、版本号后的锁/解锁线图标（全局可编辑开关，见下）、列表/树切换、搜索、筛选、碟片列表；底栏「功能」条默认收起，点或悬停后向上滑出「上传识别 / 手工建卡 / 图片管理 / 补全海报」线框图标按钮（再点、点空白或 Esc 收起）。
  • 右详情面板：点选碟片后出现；海报、简介、原图位置、定位与编辑。

当前页面标题与左上角版本标签均为 v4.0。侧栏「使用手册」打开本页（也可新标签打开 /static/docs/manual.html）。手机浏览：墙默认钉在视口顶部，仅其下侧栏列表滚动；栏目上沿有短横条把手——按住上滑隐藏墙面沉浸看卡片，再按住下滑露出墙面方便看 AR（列表区照常纵滚，不抢手势）。桌面墙仍全屏、拖拽侧栏不变。

可编辑 / 只读开关

版本号 v3.x 同一行后面有一个仅线框、无底的小锁图标，字号与版本号相同：

  • 锁（默认）：只读。可列表/树、搜索筛选、看详情、定位 AR、缩放墙图、拖侧栏看墙、调明暗；所有写操作禁用，点了会 toast「只读模式」。
  • 开锁（绿色）：可编辑。允许改碟片、手工建卡、上传识别、Stage2、补海报、喜好/旗标、删卡、改框、墙面放置等。

状态写入浏览器 localStorage（键 mywall-edit-unlocked），切换立即生效，不必刷新。首次打开默认只读，避免误改。手机布局（窄屏 / 粗指针 / 手机 UA）强制只读，忽略电脑上存的开锁状态，版本号旁的锁图标不显示；电脑桌面布局仍尊重该开关。

完整手工建墙（无模型主路径）

没有本地视觉模型时，Stage2 / 上传自动识别不可用。下面这条路径只靠手工建卡 + TMDb / OMDb / TVDB 搜索，也能把墙建起来——这是识别有限时的主用法。

  1. 开锁：点版本号旁的锁图标，进入可编辑（手机窄屏仍强制只读）。
  2. 上传特写：侧栏底「功能」→「上传识别」，上传碟脊特写或全景。可先不跑识别。
  3. 手工改碟脊框：打开碟脊框编辑器，按实际脊宽拖改 / 增删框。
  4. 可选 Stage2：本机 LM Studio 可用时再跑；不可用就跳过，不要卡在识别。
  5. 手工建卡：「功能」→「手工建卡」。中文或英文片名至少填一项；可关联刚上传的特写。
  6. 搜三平台：同一搜索框选类型（全部 / 电影 / 剧集）与来源（全部 / TMDb / IMDb / TVDB），按片名搜索，点选候选写入编号与海报。不要伪造 tmdb_id。
  7. 补海报：有 TMDb 编号后可用「从 TMDb 刷新」或侧栏「补全海报」。
  8. 墙面放置：详情里把特写框对到全景墙上（墙坐标），手机按住卡片可看 AR 定位。
  9. 手机浏览：同一 Tailscale 地址只读查看列表 / 墙 / 定位。不要在手机上改库。

API Key 在「编辑碟片 / 手工建卡」弹窗的折叠区块维护，写入本机 data/api_keys.json，界面只显示掩码。

自建 / 部署视觉模型（Stage2 可选）

自动识别依赖本机或局域网上的 LM Studio OpenAI-compatible 服务（/v1/chat/completions），不是云端视觉 API。配置以仓库根目录 config.py 与环境变量为准。

  1. 安装 LM Studio。
  2. 下载并加载视觉模型。默认模型 id：zai-org/glm-4.6v-flash（可用 VISION_MODEL 指定其它已加载模型；VISION_MODEL_AUTO=1 时按偏好表挑选，偏好含 google/gemma-4-31b-qat）。
  3. 开启 LM Studio Local Server（OpenAI 兼容，常见端口 1234）。
  4. 填写 endpoint：环境变量或 config.py 中的 LMSTUDIO_BASE（默认 http://127.0.0.1:1234）。模型若在另一台电脑，改为那台的 http://主机:端口。不要把内网 IP 写进公开文档。
  5. 跑 Flask 的机器必须能访问该 endpoint（同机、同网段、防火墙放行）。
  6. 代理 / Tun：出站 TMDb 等 API 可走 HTTPS_PROXY；若开了系统 Tun，局域网访问 LM Studio 可能被劫持——把内网段加入旁路，或只让出站 API 域名走代理。

没有可用模型时，上传分析与 Stage2 会失败。请改走「完整手工建墙」。识别不是建墙的前提。

2. 拖动侧栏 / 拖动面板

左右面板顶部有灰色把手条：

  • 左：「拖动侧栏」— 左右拖动，露出被挡住的墙面。
  • 右：「拖动面板」— 打开详情后同样可横向挪开。
  • 双击把手：偏移复位到 0。
  • 键盘：把手聚焦后用 ← / → 微调（Shift 加大步长）。

偏移会写入浏览器本地存储，下次打开仍保留。

3. 列表模式 / 树形模式

列表模式

按库中碟片平铺卡片。卡片标题第一行英文（无英文则中文），第二行灰色小字中文译名（与英文相同或无中文则不重复）。点击卡片打开详情；喜好心形在年份下方（与海报底边对齐），右侧操作为定位 / 编辑 / 标记错误 / 删除。只读模式下定位仍可用，编辑 / 旗标 / 删除 / 喜好心形不可用。

树形模式

按来源特写照片 source_image 分组。点击组头展开/折叠。

  • 组头左侧缩略图：可编辑时点击打开「调整特写在墙面上的位置」（见第 7 节）；只读时禁用。
  • 组内仍是同样的碟片卡片。

4. 搜索与筛选

  1. 在搜索框输入片名、导演、演员等关键词（输入防抖；也可点搜索按钮或回车）。
  2. 用「类型」「年份」「喜好」下拉进一步过滤；三者与关键词可组合。
  3. 喜好筛选项：全部喜好 / 绿 / 蓝 / 橙 / 未标注（对应数据库 preference 的 全部 / 1 / 2 / 3 / 0）。
  4. 统计条显示当前结果数量。

5. 碟片详情、定位、半透明特写

打开详情

点击列表/树中的碟片卡片 → 右侧出现详情（海报、年份、评分、类型、简介、导演主演）。

在原照片中的位置

  • 有来源图时显示缩略原图 + 高亮框。
  • 点击原图 → 全屏半透明放大（AR Zoom），可对照框选位置。
  • 「重新框选」：在原图上手工拉框，确认后按区域重识别/更新位置（只读时禁用）。

定位位置（墙上 AR）

  1. 详情底部点「定位位置」，或卡片上的定位线图标。
  2. 墙面出现扩散环 + 当前碟气泡；所属特写区域以半透明色块叠在墙上（若该图已标定墙面 placement）。
  3. 若碟片尚未有墙面坐标，会提示「尚未标记位置」。

定位线图标颜色：已在原图标定 bbox 为「已标注」态；否则为「未标注原照片位置」。

6. 手工编辑碟片 / 手工建卡 / 多源片名搜索

A. 编辑已有碟片

  1. 先点版本号后的锁图标解锁。卡片铅笔图标或详情「编辑」→ 「编辑碟片」对话框。
  2. 对照原图：对话框左侧（小屏可折叠「对照原图 · 碟脊」）展示该碟所属特写/原照片，并画出库内当前碟脊框（photo_offset_x/y + bbox_w/h，与详情「在原照片中的位置」同源）。滚轮或 ± 缩放、拖拽平移；「定位碟脊」会放大到框附近便于读脊上字再改片名。未标定框时仍可看全图，提示去详情「重新框选」。
  3. 可改：中文片名、英文片名、发行年份、TMDb / IMDb / TVDB 编号（均可留空）、可选关联源图。
  4. 同一搜索入口：对话框内「类型 / 来源」合在一行紧凑分段控件（小标签 + pill；窄屏可各占一行）：类型 全部 | 电影 | 剧集 + 来源 全部 | TMDb | IMDb | TVDB（默认均为「全部」）。一次「按片名搜索」并行汇总已开启且有 key 的来源；每条候选带来源徽章。同名同年不同源可并列。底部操作两行：上行搜索/刷新，下行 cancel + save（同为小号按钮，save 为主色）；长说明默认折叠。
  5. API Key（仅桌面可编辑）：对话框内可折叠「API Key」区块（默认折叠）。三行 TMDb / IMDb(OMDb) / TVDB：显示掩码（如 ••••abcd，不回显完整 key）、可粘贴新 key 保存或清除；开关控制是否「尝试调用」（关则来源分段禁用且不发请求；开但无 key 时保持提示、不假搜）。保存后立即刷新来源可用性。密钥写入本机 data/api_keys.json，不入库。
  6. 点选候选：尽量填片名、年份、海报。TMDb 条目写 tmdb_id + tmdb_media_type 并拉详情；IMDb / TVDB 写 imdb_id / tvdb_id 与海报，不伪造 tmdb_id。
  7. 从 TMDb 刷新：仅对已有 TMDb 编号有效；保留对话框片名/年份，只补海报与元数据，不改框位。无编号时会先走搜索。
  8. 侧栏 补全海报：仍按已有 tmdb_id（及 tmdb_media_type）批量补缺失海报（不改片名/框/墙坐标）。TMDb 超时请设代理如 HTTP_PROXY=http://127.0.0.1:10808。
  9. 点 save 写入库（PUT /api/discs/:id）。

B. 手工建卡（不经 Stage2）

  1. 展开侧栏底栏「功能」后点 手工建卡（书签+加号线图标）→ 同一套对话框，标题为「手工建卡」。
  2. 必填：中文片名或英文片名至少填一项（可只填其一）。年份与各源编号均可留空。
  3. 可选源图：下拉关联已有特写/全景；不选亦可建卡（source_image 为空）。有图后可在详情「重新框选」后补碟脊框与墙面位置。
  4. 搜索流程与编辑一致：选类型/来源 →「按片名搜索」→ 点选候选填 id/海报；有 TMDb 编号时也可用「从 TMDb 刷新」一并入库。
  5. 点 save → POST /api/discs；成功后刷新列表并打开该碟详情。

若 Flask 以 DEBUG=False 运行，新增/改过的 API 路由需重启服务才会生效。

7. 树视图：特写在墙面位置（多特写托盘）

  1. 切到树形模式。
  2. 解锁编辑后，点击某组头左侧缩略图。
  3. 弹窗上方托盘列出全部特写：点击或拖到墙面开始编辑当前框。
  4. 框内拖拽移动；四角手柄缩放；可切换托盘中其他特写依次调整。
  5. 可选「保存后按 photo_offset 重算对应图下所有碟片的墙面坐标」（默认勾选）。
  6. 「保存位置」写入；「取消」或点遮罩关闭。

上传流程第 4 步也有批量位置标记（拖框 + 右下角缩放 + 滚轮），可与这里互补。Stage2 导入时若尚未标定 width_ratio/height_ratio，仍会写入碟片（墙面坐标可能需之后重算）。

8. 上传识别

需先解锁编辑。展开侧栏底栏后点「上传识别」打开向导。v3.8 起，步骤 1 的已上传照片列表可走「手工碟脊框 → Stage2」高质量路径（与旧四步批量 OCR 分析并存）。

A. 经典四步（批量分析）

  1. 上传：拖入或选择碟脊特写（JPG/PNG/WebP，可多选）。可勾选已有照片删除或重新分析。
  2. 分析：后端批处理（OCR + 视觉），显示进度。
  3. 匹配：确认 TMDb 候选；可改选、手动搜索、标定碟脊、视觉验证。最后「确认所有匹配并保存」。
  4. 位置标记：在墙面背景上摆放本批照片框 → 保存或跳过。

B. 手工碟脊框 → Stage2（推荐高精度）

  1. 打开「上传识别」，在已上传照片列表中勾选或点缩略图右上角线框裁剪图标。
  2. 点工具栏「修正碟脊框」（需恰好选 1 张）→ 弹出编辑器（嵌入 spine_boxes_editor）。
  3. 若尚无框：空模板起步，用「＋ 添加框」或空白处拖拽；有历史框则直接改。改完点保存到服务端（快捷键 S）。角标数字表示已存框数。
  4. 勾选一张或多张已有碟脊框的照片 →「Stage2 识别」。
  5. 后台异步跑视觉读标题 + TMDb 匹配，并写入 discs（默认重置同图旧碟）。进度在分析步骤区显示；完成后主列表可看到新碟片。

Stage2 依赖本机可达的 LM Studio 与 TMDb（见第 12 节）。无框时无法开跑，会提示先保存框。

关闭上传弹窗会提示进度可能丢失，确认后再关。

9. 图片管理

  1. 解锁后展开侧栏底栏，点「图片管理」→ 网格列出已上传图（特写 / 全景标签）。
  2. 单张：重新识别、删除。
  3. 多选：批量重新识别、批量删除；可用全选。

碟脊框文件按 wall_image.id 存在 data/spine_boxes/；Stage2 结果在 data/spine_results/。图片管理删除图时请知悉：当前以库与上传文件为主，框 JSON 可能仍留在磁盘（可手工清理）。

10. 碟脊框相关

应用内（主界面有入口）

  • 上传窗列表：「修正碟脊框」/ 缩略图右上角线框图标 → 嵌入编辑器，保存到服务端（第 8 节 B）。
  • 上传匹配步骤中：「标定碟脊」→ bbox 编辑器在原图上拉框（滚轮缩放、右键/中键拖动画布）— 面向单碟校正。
  • 详情「重新框选」：同一套在线编辑器，用于修正原图位置 / 区域重识别。

离线碟脊框编辑器

独立页：/static/spine_boxes_editor.html。用于修正 stage1 的 spine_boxes_*.json：

  1. 选原图 + stage1 JSON → 加载。
  2. 拖框改位置/大小；空白处拉框或「＋ 添加框」补漏检；可复制/删除。
  3. 导出 spine_boxes_*_edited.json，再交给离线 stage2 / import 脚本。

嵌入模式（上传窗）与离线模式共用同一套编辑逻辑；嵌入模式多了「保存到服务端」，不再依赖本地选文件。

与离线脚本的关系

  • 网页 Stage2 ≈ scripts/recognize_spines_with_tmdb.py + scripts/import_spines_to_db.py（Flask 直接调用同一函数）。
  • 离线 stage1 仍用 scripts/generate_spine_boxes.py；网页端目前不强制先跑 stage1——可空框手工加，或把离线 JSON 内容贴进服务端文件（高级）。
  • 命令行批处理示例仍见 scripts/_batch_stage2.py（含本机代理环境变量）。

11. 卡片其他操作

  • 喜好心形：在年份下方、左对齐，竖直落在海报底边一线（无背景圆圈，仅图标）。空心=未标注；实心绿 / 蓝 / 橙为三档色阶。悬停心形后向右滑出一条圆角色条（绿/蓝/橙 + 空心清除）；心形与色条同属一块热区，可直接移入点选。再点当前已选色或点空心可清除。移开热区即收起，未点选不写入。只读时不可改。
  • 旗标：标记 / 取消「识别有误」；墙上标记也会带警示样式。只读时不可改。
  • 删除：双重确认后从库中删除该碟。只读时不可用。
  • 可编辑时按住 Shift 拖墙上碟片标记可改坐标；只读时禁用。
  • 点击墙面空白（墙图）可关闭已打开的详情面板。
  • Esc：优先关 AR 放大 / 碟脊框编辑器 / 手册 / 特写位置弹窗 / 详情 / 管理等。

12. 工具 / 外部能力依赖

以下依据仓库内真实配置与脚本注释整理；密钥本身不写入手册。

Flask 本机服务

  • 入口：项目根目录运行 python app.py（或等价方式启动 Flask）。
  • 默认监听 0.0.0.0:5000；本机浏览器访问 http://127.0.0.1:5000。
  • 静态资源：/static/…；上传图 /uploads/…；素材照片 /photos/…。

本机 API Key（推荐）

  • 桌面「编辑碟片 / 手工建卡」弹窗 → 折叠区块 API Key：维护 TMDb、IMDb(OMDb)、TVDB。
  • 持久化：data/api_keys.json（未入库，已加入 .gitignore）。保存后 Flask 热读内存 config，不必重启即可搜。
  • 接口：GET /api/settings/keys 只返回掩码与开关；PUT 更新某源 key / enabled。
  • 开关：关 → 来源分段禁用、搜索跳过、不 400；开但无 key → 保持「未配置」提示、不假搜。
  • 回退顺序：json 里显式写了 api_key（空字符串=已清除）→ 环境变量 → config.py。
  • 勿把真实密钥写进文档或提交到仓库。

TMDb API

  • 用途：按识别出的片名搜片、拉详情/海报；多源搜索中的默认主源。
  • 配置：弹窗 API Key，或环境变量 TMDB_API_KEY / TMDB_ACCESS_TOKEN，或 config.py 回退（离线脚本仍可读 config）。
  • 申请：themoviedb.org/settings/api。
  • 无 key 或已关闭：来源切换里的 TMDb 禁用；不会假搜索。

OMDb（IMDb 元数据）

  • 用途：合法代理访问 IMDb 片名搜索与海报；写入可空字段 imdb_id（如 tt0133093）。
  • 配置：弹窗 API Key，或环境变量 OMDB_API_KEY（见项目根 .env.example）。
  • 申请：omdbapi.com/apikey.aspx（免费档即可）。
  • 无 key 时：来源切换里的 IMDb 禁用并悬停/点击提示「未配置 OMDB_API_KEY」；不会发起假搜索。开关关闭则提示「已关闭该来源的 API 调用」。

TheTVDB v4

  • 用途：剧集/电影片名搜索；写入可空字段 tvdb_id；海报能取则写入 poster_url。
  • 配置：弹窗 API Key，或环境变量 TVDB_API_KEY / THETVDB_API_KEY。
  • 申请：thetvdb.com/api-information 注册项目获取 apikey。
  • 无 key 时：来源切换里的 TVDB 禁用并提示；不会假搜索。

LM Studio / 本地视觉模型

  • 代码默认基址：http://127.0.0.1:1234（LMSTUDIO_BASE，见「自建视觉模型」）（可用环境变量 LMSTUDIO_BASE 覆盖）。
  • 默认模型 id：zai-org/glm-4.6v-flash；可用 VISION_MODEL=… 强制指定，或 VISION_MODEL_AUTO=1 按偏好表在已加载模型中挑选（偏好含 google/gemma-4-31b-qat 等）。
  • 识别 / Stage2 / 区域重识别都依赖该 OpenAI 兼容 /v1/chat/completions 接口；服务不可达时上传分析与 Stage2 会失败。
  • 需保证跑 Flask 的机器能访问该局域网地址（同网段 / 路由 / 防火墙放行）。

代理（TMDb / OMDb / TVDB）

  • tmdb_client / omdb_client / tvdb_client 会读取环境变量 HTTP_PROXY / HTTPS_PROXY（及小写形式），缺省回落到 config.TMDB_HTTP_PROXY（常见 http://127.0.0.1:10808）。
  • 离线批处理脚本 scripts/_batch_stage2.py 实践中写死示例代理 http://127.0.0.1:10808（注释说明直连易超时）。网页 Flask 进程若未继承 shell 代理，仍可用上述默认。
  • 注意：开系统 Tun 时，局域网访问 LM Studio可能被劫持；常见做法是把内网段加入 Tun 旁路，或仅对出站 API 域名走代理。

离线脚本与编辑器

  • scripts/generate_spine_boxes.py：stage1，视觉检出碟脊 bbox → spine_boxes_*.json。
  • scripts/recognize_spines_with_tmdb.py：stage2，裁剪框 → 读标题 → TMDb。
  • scripts/import_spines_to_db.py：把 stage2 结果写入 SQLite discs（需能定位 wall_images；完整墙面坐标依赖已标定的 width/height_ratio）。
  • 编辑器页：static/spine_boxes_editor.html（离线文件模式或 ?embed=1&image_id= 嵌入模式）。

本地数据

  • SQLite：data/mywall.db（碟片、墙面图元数据等）。
  • 本机 API Key：data/api_keys.json（不入库；手册与仓库不写真实 key）。
  • 上传文件：uploads/；素材/墙图：photos/（全景默认 photos/test-wall.jpg）。
  • 碟脊框：data/spine_boxes/{wall_image_id}.json；Stage2 结果：data/spine_results/{id}.json。
  • 应用日志：项目根 app.log。
